# ИС «НефтеЗакупки» — система анализа рынка и оптимизации закупок МТР

Информационная система для управления закупками материально-технических ресурсов (МТР) нефтедобывающего предприятия.

**Стек:** Django 4.2 + DRF · React 18 + Vite · PostgreSQL 16 · Nginx · Docker Compose

---

## Быстрый запуск через Docker Desktop

### Что нужно установить

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) для Windows

### Шаг 1 — Открыть терминал в папке проекта

Откройте папку `oil_procurement` в проводнике.  
Кликните правой кнопкой мыши на пустом месте → **«Открыть в терминале»** (или PowerShell).

### Шаг 2 — Собрать и запустить все контейнеры

```bash
docker compose up --build -d
```

Эта команда:
1. Соберёт образ **backend** (Django + Gunicorn)
2. Соберёт образ **frontend** (React → собирается через Node 20, отдаётся через Nginx)
3. Запустит **PostgreSQL** (база данных)
4. Запустит **Nginx** (обратный прокси на порту 80)
5. Автоматически выполнит миграции и загрузит демо-данные

Первый запуск занимает **3–7 минут** (скачивание образов + сборка React).

### Шаг 3 — Открыть сайт

Перейдите в браузере: **http://localhost:8080**

## Управление через Docker Desktop (графический интерфейс)

После запуска `docker compose up` откройте **Docker Desktop**:

| Что нажать | Что делает |
|---|---|
| Вкладка **Containers** | Показывает все 4 контейнера: `oil_nginx`, `oil_backend`, `oil_frontend`, `oil_db` |
| Кнопка ▶ (Play) рядом с контейнером | Запускает остановленный контейнер |
| Кнопка ⏹ (Stop) | Останавливает контейнер |
| Кнопка 🗑 (Delete) | Удаляет контейнер (данные в volumes сохраняются) |
| Кнопка **Logs** (значок листа) | Показывает логи контейнера в реальном времени |
| Кнопка **Terminal** (>_) рядом с `oil_backend` | Открывает bash внутри контейнера Django |
| Вкладка **Volumes** | Управление томами с данными БД и статикой |

### Как перезапустить проект целиком

В Docker Desktop → вкладка **Containers** → найдите строку с именем проекта → кнопка **Stop** → затем **Start**.

Или через терминал:

```bash
# Остановить
docker compose stop

# Запустить снова
docker compose start

# Остановить и удалить контейнеры (данные в volumes сохранятся)
docker compose down

# Пересобрать после изменений в коде
docker compose up --build -d
```

## Функционал системы

### Каталог МТР
- Справочник материалов с кодом МТР, техническими характеристиками, категорией и критичностью
- Складские остатки на карточке каждого материала
- График динамики цен по поставщикам (Recharts)

### Складской учёт
- Учёт остатков по местам хранения: всего / зарезервировано / свободно
- Подсветка позиций ниже минимального запаса

### Заявки на закупку (Workflow)
```
Черновик → На рассмотрении → Утверждена → Заказ размещён → Исполнена
                           ↘ Отклонена → (возврат в Черновик)
```
- Инициатор создаёт заявку и добавляет позиции МТР
- Закупщик анализирует КП и выбирает лучшего поставщика
- Руководитель утверждает или отклоняет

### Анализ рынка — сравнительная таблица КП
Каждое ценовое предложение получает балл по трём критериям:

| Критерий | Плановая | Аварийная |
|---|---|---|
| Цена | 60% | 20% |
| Срок поставки | 20% | 70% |
| Надёжность поставщика | 20% | 10% |

### Аналитика
- **Дашборд** — сводная статистика, пирог заявок по статусам, топ материалов
- **Динамика цен** — линейный график по выбранному материалу в разрезе поставщиков
- **Отчёт по дефициту** — позиции заявок к закупке + МТР ниже минимума
- **Сводные отчёты** — заявки по месяцам, заказы по статусам, топ поставщиков

### Ролевая модель

| Роль | Доступ |
|---|---|
| Инициатор | Создание заявок, каталог |
| Закупщик | Всё + КП, поставщики, заказы |
| Аналитик | Каталог, склад, аналитика, КП |
| Руководитель | Утверждение заявок, аналитика |
| Администратор | Полный доступ + управление пользователями + журнал операций |

## Интеллектуальный мониторинг поставщиков

Модуль автоматически собирает данные о ценах с сайтов поставщиков, сопоставляет найденные товары с внутренним каталогом МТР и пополняет базу ценовых предложений (PriceQuote), которые уже используются существующей логикой подбора лучшего поставщика.

### Принцип работы

```
Сайт поставщика
  → Парсер (requests + BeautifulSoup)
  → Нормализация цены / наличия / срока поставки
  → ИИ-сопоставление с каталогом МТР (RapidFuzz)
  → ParsedProduct (все найденные товары)
  → Если match_score >= 35% и цена найдена:
      → Создание / обновление PriceQuote
  → Существующая система сравнения КП использует PriceQuote
```

### Модели данных

| Модель | Назначение |
|---|---|
| `ParsingSource` | Источник парсинга: URL, поставщик, категория, активность |
| `ParsedProduct` | Найденный товар с ценой, наличием, оценкой сопоставления |
| `ParsingRun` | Журнал запусков: статистика, ошибки |
| `SupplierCandidate` | Кандидаты новых поставщиков для ручной модерации |
| `SupplierDiscoveryQuery` | Поисковые запросы для модуля discovery |
| `SupplierDiscoveryRun` | Журнал запусков discovery |

### ИИ-сопоставление товаров

Сервис `core/services/ai_matching.py` реализует:

1. **Нормализация текста** — нижний регистр, ё→е, удаление стоп-слов, нормализация Ду/DN, Ру/PN, МПа, кВт
2. **Классификация категории** — по ключевым словам: КИПиА, Запорная арматура, Насосное оборудование, Кабельная продукция, Трубы, Химические реагенты, Электродвигатели, Подшипники
3. **Нечёткое сопоставление** — RapidFuzz: `token_sort_ratio`, `token_set_ratio`, `partial_ratio` + бонус за совпадение технических токенов (Ду100, DN50, Ру16, числа, марки)
4. **Объяснение решения** — `ai_comment` содержит категорию, сопоставленный МТР, уверенность и вывод о создании PriceQuote

### Создание PriceQuote

- При `match_score >= 35%` и наличии цены — автоматически создаётся или обновляется `PriceQuote`
- Поля: `price`, `delivery_days`, `quote_date`, `notes` (источник URL), `logistics_notes` (наличие), `payment_terms` ("Автоматический сбор данных")
- Если PriceQuote с таким `supplier + material` уже есть — цена и срок обновляются
- Существующая система (`RequestItem.get_comparison_quotes()`) немедленно начинает использовать эти данные

### Управление через Django Admin

**Admin → Источники парсинга** — список всех источников, статус, последние ошибки, можно включать/отключать прямо в таблице.

**Admin → Найденные товары** — все спарсенные товары с оценкой сопоставления и ИИ-комментарием.

**Admin → Запуски парсинга** — история запусков: сколько товаров найдено, сколько PriceQuote создано/обновлено.

**Admin → Кандидаты поставщиков** — новые сайты для ручной проверки. Actions:
- **"Одобрить"** → создаётся `Supplier` + неактивные `ParsingSource` (включить вручную)
- **"Отклонить"** → статус rejected

### Запуск локально

```bash
# Заполнить базу поставщиков и источников
python manage.py seed_parsing_sources

# Заполнить поисковые запросы для discovery
python manage.py seed_supplier_discovery_queries

# Запустить парсинг (--dry-run для проверки без сохранения)
python manage.py parse_supplier_prices --limit 5
python manage.py parse_supplier_prices --limit 5 --dry-run

# Конкретный источник
python manage.py parse_supplier_prices --source-id 3

# Импорт кандидатов из CSV
python manage.py import_supplier_candidates --csv suppliers.csv
python manage.py import_supplier_candidates --csv suppliers.csv --analyze
```

### Запуск на сервере через Docker

```bash
# Применить новые миграции
docker compose exec backend python manage.py migrate

# Заполнить источники парсинга
docker compose exec backend python manage.py seed_parsing_sources

# Запустить парсинг (limit рекомендуется в production)
docker compose exec backend python manage.py parse_supplier_prices --limit 5

# Посмотреть результат в Admin
# http://your-server/django-admin/ → Найденные товары / Ценовые предложения
```

**Важно:** парсинг не запускается автоматически при старте сайта. Только через management command вручную или по расписанию (cron).

## Поиск новых поставщиков

### Принципы безопасности

- Модуль **не сканирует интернет бесконтрольно**
- Для автоматического поиска через поисковые системы требуется официальный API (переменная `SERPAPI_API_KEY`)
- Без API-ключа используется **CSV-импорт** (`import_supplier_candidates --csv`)
- Все найденные сайты сохраняются как `SupplierCandidate` со статусом `new`
- Финальное включение в активный парсинг делает **администратор вручную** в Django Admin

### Рейтинг поставщика

Рассчитывается на основе открытых признаков сайта:

| Признак | Баллы |
|---|---|
| Есть каталог (ссылки /catalog, /products и т.п.) | +20 |
| Найдены карточки товаров | +20 |
| Найдены цены на странице | +15 |
| Найдены контакты | +10 |
| Найдены реквизиты / ИНН | +10 |
| Есть доставка по РФ | +10 |
| Определены технические категории | +10 |
| Сайт работает по HTTPS | +5 |
| Сайт не отвечает | −20 |
| Нет контактов | −15 |
| Нет признаков товарного каталога | −15 |
